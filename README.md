# make-knowledge-cards

把一篇文章拆成一组可复习的知识卡片：一张卡只讲一个知识点，四要素齐全，每句话都能追溯回原文。

粘贴一段文字，或指定一个本地 Markdown / TXT 文件，就能拿到一组可以直接放进笔记、也可以合上原文自测的卡片。张数通常在 5-8 张之间，材料不足时会少于 5 张，甚至不出卡。

## 1. 项目解决什么问题

让 AI“把文章做成卡片”，常见三种失败：

- **换个排版抄一遍**。把原文的小标题直接当卡片标题，读者复习时只看到目录，看不到任何理由。
- **凑数**。为了凑够 5 张，把一句话拆成三张，或者给每张卡补一段宽泛的背景。
- **编造**。原文没说的机制、原因、案例被顺手补上，甚至把经验建议包装成“研究表明”，卡片看起来比原文更权威。

这个 Skill 把这三件事变成可判定的规则，而不是写作建议：

| 问题 | 对应机制 |
| --- | --- |
| 切不开、一张卡塞多个要点 | 用标题测试、拆解测试、归属测试判定“一个知识点”的边界 |
| 凑数 | 张数由知识点数量查表决定，0 个知识点就明确不出卡 |
| 编造 | 保真红线九条：数字与限定词、禁用类比、观点归属、禁止套统计外衣 |

结果是一组能独立阅读的卡片：删掉任意一张，其余仍然完整可懂；只看卡片的人不会漏掉文章的主结论。

## 2. 主要功能

- **读取输入**：接受对话中粘贴的正文，或本地 `.md` / `.markdown` / `.txt` 文件；长文分段读完后统一切卡，不会只读开头就产出。
- **知识点提取与分级**：按 P0（核心论点、因果机制、方法步骤、关键数字、误区纠正、作者的限定澄清）、P1（前提边界、对照差异、代价风险）、P2（背景铺垫、情绪表达、口号、无解释的事实罗列）三层筛选。
- **原子化切卡**：三个测试保证一张卡只讲一个知识点；同时处理“推论”——若 A 只是 B 的直接推论且没引入新变量，并入 B 而不单独立卡。
- **去重与合并**：识别同义重述、总分结构、并列条目、正反例、前后呼应五种重复形态，只保留表述最清楚的一版。
- **数量自适应**：8 个以上知识点取前 8 并说明舍弃了什么；5-7 个全出；3-4 个、1-2 个如实少给；0 个则不出卡。
- **四要素卡片**：标题（单一论断）、核心知识（一句话结论）、简明解释（为什么 / 怎么做 / 何时不成立）、例子或自测题（原文有例子用例子，没有就给一问一答）。
- **保真校验**：数字、单位、术语与原文一致，模糊限定词随数字保留；禁止添加原文没有的类比；观点类文章整组声明为作者主张。
- **语言跟随原文**：英文原文出英文卡片，中文出中文，术语保留原写法。
- **诚实退出**：遇到资讯型短文或纯口号文本时，说明缺什么、给替代方案，而不是硬凑。

不支持：网页抓取、PDF / docx / epub、Anki 导出、图形界面。遇到这类输入会说明限制并给出替代路径，不会假装已读取。

## 3. 安装方法

本 Skill 是纯提示词技能，没有脚本、没有依赖，安装就是把目录放对位置。

**方式一：项目级**（团队共享，随仓库分发）

```bash
# 目录名必须与 SKILL.md 里的 name 一致
your-project/skills/make-knowledge-cards/
```

**方式二：用户级**（本机所有项目可用）

```bash
cp -r skills/make-knowledge-cards ~/.workbuddy/skills/
```

Windows 上可用：

```powershell
Copy-Item -Recurse skills\make-knowledge-cards "$env:USERPROFILE\.workbuddy\skills\"
```

目录名保持 `make-knowledge-cards`，与 `SKILL.md` 的 `name` 字段一致——改名会导致技能无法被识别。

`agents/openai.yaml` 提供运行环境所需的元信息：展示名、一句话简介、默认提示语，以及 `policy.allow_implicit_invocation`（允许根据用户意图自动触发，不要求显式点名）。

装好后在对话里说“把这篇做成知识卡片”即可触发，不需要记住技能名。

## 4. 使用方法

**直接粘贴正文**

```
把下面这篇文章做成知识卡片：

<粘贴正文>
```

**指定本地文件**

```
用 make-knowledge-cards 处理 tests/samples/02-interview.md
```

**要求保存成文件**

```
做成卡片并保存到 notes/
```

默认只在对话里输出。明确要求保存时，才写入 `<原文件名>-知识卡片.md`；没有来源文件名则写 `knowledge-cards.md`。

**一次给多个文件**要分成多组处理，技能不会把它们混成一组卡片。

## 5. 输入输出示例

**输入**（节选）：

> 睡眠不足对记忆的影响主要发生在巩固阶段。人在深度睡眠时，海马体会把白天形成的短期记忆反复回放到新皮层，完成从临时存储到长期存储的转移。因此熬夜背书的效果往往很差：编码阶段并没有问题，被切断的是当晚的转移过程。需要注意的是，这种损害不能靠周末补觉完全弥补，回放的时间窗口集中在入睡后的前三个睡眠周期。

**输出**：

```markdown
# 《睡眠与记忆》知识卡片（2 张）

> 来源：用户粘贴文本 ｜ 识别知识点 2 个 ｜ 成卡 2 张

### 卡片 1｜睡眠不足损害记忆，主要发生在记忆巩固阶段

**核心知识**：睡眠不足对记忆的破坏不在“记不住”，而在“存不下”。

**简明解释**：深度睡眠时海马体将白天的短期记忆回放给新皮层，完成向长期存储的转移。熬夜切断了这一转移过程，编码环节本身并未受损，所以表现为“当时记住了，之后想不起来”。

**例子 / 自测**：熬夜背书效果差——编码正常，被切断的是当晚的巩固过程。

### 卡片 2｜补觉无法完全挽回已损失的巩固效果

**核心知识**：记忆回放集中在入睡后的前三个睡眠周期，错过即错过。

**简明解释**：原文指出这种损害不能靠周末补觉完全弥补。原因是回放的时间窗口集中且靠前，事后延长睡眠无法回溯已经错过的窗口。

**例子 / 自测**：
问：为什么周末睡到中午，也补不回熬夜那晚背的内容？
答：回放窗口集中在入睡后前三个周期，事后补觉无法回到该窗口。

---

**覆盖说明**：原文仅提供上述两个知识点，未凑足 5 张。
```

这个例子同时展示了“不凑数”：原文只有两个知识点，就只给两张卡，并在覆盖说明里写清楚。

**输出的固定结构**：一级标题（篇名 + 张数）→ 来源引用块（来源 / 识别知识点数 / 成卡数）→ 卡片序列 → 覆盖说明。观点类文章会在引用块后多一行“本文为观点文章，以下均为作者主张”的声明。

**单个卡片固定四要素**：

| 要素 | 要求 |
| --- | --- |
| 标题 | 单一论断，可判断真假；不用疑问句，不照抄小标题 |
| 核心知识 | 一句话结论，不超过 40 字，脱离上下文也能独立成立 |
| 简明解释 | 2-4 句，至少补齐“为什么 / 怎么做 / 何时不成立”中的一项 |
| 例子 / 自测 | 二者取一；有原文例子用原文，没有就给一问一答 |

## 对特殊文本的处理

| 文本类型 | 处理方式 |
| --- | --- |
| 条目型（“七个要点”） | 条目数是提纲不是知识点数；命令式标题改写成它成立的原因，避免变成目录的排版复刻 |
| 纯清单（只列条目、不给理由） | 走规范模式：不编造“为什么”，如实声明“原文未说明理由”，卡片定位为操作规范 |
| 观点型（评论、专栏） | 整组声明“均为作者主张”，解释只复述作者的论证路径，不代为续写论据 |
| 资讯型（发布会短讯、快报） | 只有事实没有解释时不出卡，改用“为什么不出卡”+“可以改做什么”的结构 |
| 英文原文 | 卡片语言跟随原文，术语保留原写法，限定词（usually / widely cited）随数字一起保留 |

## 项目结构

```
article-to-knowledge-cards/
├── README.md
├── LICENSE
├── skills/
│   └── make-knowledge-cards/
│       ├── SKILL.md              # 技能本体：工作流、判定规则、卡片模板、保真红线
│       └── agents/
│           └── openai.yaml       # 元信息：展示名、简介、默认提示语、触发策略
└── tests/
    ├── samples/                  # 6 个测试输入
    └── expected/                 # 对应的期望产出
```

`SKILL.md` 是唯一的行为定义文件。没有脚本、没有 assets、没有外部依赖。

## 测试

`tests/` 下保留了 6 个不同类型的用例，覆盖上面每一种文本类型：

| 用例 | 类型 | 检验点 |
| --- | --- | --- |
| `01-quic.md` | 机制密集的技术科普 | 8 个知识点如何取舍；数字与限定词是否保真 |
| `02-interview.md` | 条目型方法论 | 是否退化为“条目分行抄写”；是否给经验建议套统计外衣 |
| `03-opinion.md` | 观点评论 | 是否把作者主张写成客观事实；是否隐去作者自承的局限 |
| `04-thin.md` | 资讯型短讯 | 信息不足时是否强行凑数 |
| `05-checklist.md` | 纯清单、无理由 | 是否替原文编造“为什么” |
| `06-english.md` | 英文 | 语言是否跟随原文；术语与限定词是否保留 |

`tests/expected/` 是对应的产出，可用于回归比对。

## 自定义

改 `SKILL.md` 里这三处就够了：

- **张数区间**：`数量决策` 表格。
- **卡片字段**：`卡片模板`，字段名与顺序都在这里定义。
- **严格程度**：`保真红线`，例如允许补充背景知识时，可放宽第 1 条。

改完用官方的 skill-creator 校验脚本检查格式（该脚本来自 skill-creator 技能，不在本仓库内，需自行安装或使用已有副本）：

```bash
python <skill-creator>/scripts/quick_validate.py skills/make-knowledge-cards
```

校验通过会输出 `Skill is valid!`。

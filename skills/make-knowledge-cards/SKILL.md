# Make Knowledge Cards

## 概述

把一篇文章压缩成一组可独立复习的卡片：一张卡只承载一个知识点，四要素齐全（标题 / 核心知识 / 简明解释 / 例子或自测），且每一句都能追溯到原文。核心难点不是排版，而是**选得准、切得开、不注水、不编造**。

默认在对话里直接输出 Markdown 卡片组。用户明确要求保存时才写文件。

## 适用范围

支持：

- 用户直接粘贴的文章、笔记、讲稿正文
- 本地 `.md`、`.markdown`、`.txt` 文件（读取全文后再处理）

不支持，且不要假装支持：

| 输入 | 处理方式 |
| --- | --- |
| 网页链接、URL | 说明暂不支持抓取网页，请把正文粘贴过来 |
| PDF、docx、epub | 说明暂不支持该格式，请先转成 .md/.txt 或粘贴正文 |
| 导出 Anki / apkg / CSV 牌组 | 说明不支持，本 Skill 只产出 Markdown 卡片 |
| 图形界面、网页应用 | 不支持，交付物是文本卡片 |

若用户要的是“总结一下 / 写个摘要”，不要套用卡片格式——直接总结。卡片是给记忆和自测用的，不是摘要的排版变体。

## 工作流

1. **确认输入**。粘贴文本直接开工，不要让用户重发。文件先读全文；文件很长时分段读完再统一切卡，禁止只读开头就产出。多个文件分别出卡组，不要混成一组。
2. **判断文本类型**。先分清是解释型（有机制、方法、因果）、条目型（“七个要点”）、观点型（评论、专栏）、还是资讯型（只报事实）。类型决定后面的切法，见「两类难处理的文本」。
3. **拆解知识点**。通读后列出候选清单（内部草稿，不必展示），按优先级阶梯标注 P0/P1/P2。
4. **去重与合并**。同一主张的多次表述只留一张。
5. **决定张数**。按知识点实际数量定，落在 5-8 区间；不足就少给，不凑。
6. **写卡**。严格用统一模板，四要素齐全。
7. **自检**。逐条跑完自检清单再交，发现问题就地改。
8. **输出**。卡片组 + 覆盖说明；零知识点时改用不出卡的专用格式。

## 什么算“一个知识点”

这是最容易失手的地方。用三个测试判定：

- **标题测试**：能否写成一个不含“和 / 以及 / 同时 / 另外”的单一陈述句？需要并列两个谓语，通常是两个知识点。
- **拆解测试**：把卡内内容拆成两句，若两句各自独立成立且有独立价值 → 拆成两张；若第二句只是在解释第一句 → 保持一张。
- **归属测试**：删掉另一张卡，这张是否仍然完整可读？若不能，两张耦合过紧，考虑合并或重划边界。

章节名（“背景”“方法”“结论”）不是知识点，不要拿它当标题。标题应是可判断真假的陈述，例如“延迟满足的关键变量是注意力分配”而不是“延迟满足的重要性”。

**推论的处理**：若 A 卡的核心知识只是 B 卡的直接“所以”，且没有引入新变量，并入 B 卡，不单独立卡。若引入了新变量（网络延迟高低、设备性能、用户类型、时间窗口），则可独立成卡——此时它解释的是“在什么条件下更明显”，本身有独立价值。

## 提取优先级

**P0 优先成卡**

- 核心论点、文章想让人相信的那句话
- 定义、判定标准、分类依据
- 因果机制：为什么会这样、什么导致什么
- 可复用的方法、步骤、检查项
- 关键数字、阈值、比例、时间窗口
- 作者明确指出的误区及其纠正
- 作者的限定与澄清（“需要注意的是”“我并非主张……”）——这类内容防止误读，价值不低于正面论点

**P1 有余量时收录**

- 前提假设与适用边界（在什么条件下才成立）
- 对照与差异（A 与 B 的分野）
- 代价、风险、失效场景

**P2 不进卡片**

- 背景铺垫、行业综述、客套开场
- 作者个人经历与情绪表达（除非它本身就是论据）
- 修辞、口号、金句（没有解释支撑的态度表达）
- 引流、课程推荐、自我推销
- 无解释的事实罗列
- 同一意思的重复表述

判断口诀：**能改变读者下一次判断或行动的内容进卡，只改变读者情绪的不进卡。**

## 两类难处理的文本

### 条目型（“七个要点”“五个方法”“三大原则”）

这类文章最容易被做成“把条目分行抄一遍”。三条纪律：

1. **条目数是提纲，不是知识点数。** 先判断条目之间的关系：若是同一方法的连续步骤，合成一张方法卡，步骤写进解释；若各条可独立应用、无顺序依赖，才一条一卡。
2. **条目是操作命令，核心知识要转成它成立的原因。** “问过去的行为，不问未来的意愿”是命令；核心知识应写成“人对未来行为的预测不可靠，只有过去的行为可核查”。否则卡片只是换了排版的目录，读者复习时记不住任何理由。
3. **解释只能用原文给过的理由。** 原文只列条目、不解释原因时，解释里只写操作方式与原文出现过的限定，不得自行补机制。
4. **通篇不给理由的纯清单，改走规范模式。** 此时不强行写“为什么”，而是：
   - 核心知识写成规范陈述（“议程应提前 24 小时发出”“参会人数上限为 6 人”），只保留原文给出的边界：时间、人数、角色、顺序。
   - 解释栏只交代原文限定的执行口径，并明确写一句“原文未说明理由”。
   - 严禁用“这样能提高效率”“有助于对齐认知”这类通用好处去填空——这是最省事、也最常见的编造。
   - “例子 / 自测”改用符合性判断（“这种情形是否符合该条”），不要编场景。
   - 覆盖说明里声明：整组卡片是操作规范而非原理。
   纯清单的卡片价值在于可执行、可核对，不在于解释，交付时如实说明即可，不要为了好看而拔高。

### 观点型（评论、专栏、社论）

1. 卡片组开头声明“本文为观点文章，以下均为作者主张”，避免把作者判断读成客观事实。
2. 标题保持论断形式，归属信息放在声明与解释里，不必每张标题都加“作者认为”，否则八张卡全是同样前缀。
3. **简明解释写作者的论证路径**：从哪个前提推到哪个结论，只用原文出现过的论据。作者的推理是你复述的对象，不是你可以续写的地方。
4. 作者自承的局限（缺乏数据、无法做对照实验、样本偏差）必须写进覆盖说明，不得隐去——隐去会让卡片显得比原文更权威。
5. “我并非主张……”这类澄清要成卡。它界定论点的边界，防止读者把主张放大成极端版本。

## 去重与合并

- **同义重述**：保留表述最清楚的一版，把其他版本多出来的细节并入“简明解释”，不单独出卡。
- **总分结构**：总述句与分述重复时，卡片落在更具体的分述上，总述句作为标题或解释的引子。
- **并列条目**：按上面「条目型」的三条纪律处理。
- **正例反例讲同一件事** → 合成 1 张，把对比放进“例子”位置。
- **前后呼应**：文章开头提出、结尾回扣的同一主张，只出 1 张。

## 数量决策

| 独立知识点数 | 输出 |
| --- | --- |
| 8 个及以上 | 出 8 张，按 P0 → P1 取前 8，末尾说明还有几个次要知识点未收录 |
| 5-7 个 | 全部输出 |
| 3-4 个 | 输出 3-4 张，并说明原文有效知识点就这么多 |
| 1-2 个 | 输出 1-2 张，用正常格式，覆盖说明写明信息不足的具体表现，**不要拆成多张** |
| 0 个 | 不出卡，改用「零知识点时的输出」格式 |

硬约束：**张数由知识点数量决定，不由“要凑够 5 张”决定。** 4 张扎实的卡优于 8 张里掺 3 张水的。禁止用换词复述、拆句、补充宽泛背景来凑数。

资讯型文本（发布会短讯、财报快报、活动通知）通常落在 0-2 个知识点。判断依据只有一条：**文中有没有解释**（为什么这样、怎么做、什么条件下不成立）。只有事实没有解释，就不成卡。

## 卡片模板

逐字沿用以下结构，字段名不要改，顺序不要调：

```markdown
### 卡片 1｜标题写成单一陈述句

**核心知识**：一句话结论，不超过 40 字，脱离上下文也能独立成立。

**简明解释**：2-4 句，说清为什么成立、怎么运作、在什么条件下适用。只写原文支撑的内容。

**例子 / 自测**：原文的实例、数据或场景（优先用原文原句）。
```

原文没有例子时，“例子 / 自测”字段改成两行问答，不要写成一段：

```markdown
**例子 / 自测**：
问：一道只靠本卡内容就能回答的问题。
答：一句话作答，不引入新知识。
```

字段要求：

- **标题**：单一论断，可判断真假；不用疑问句，不用“浅谈 / 关于 / 探析”。
- **核心知识**：结论式陈述，不是话题，也不是空洞的号召。禁止“XX 很重要”“需要重视 XX”这类无信息量的句子。纯清单模式下可写规范陈述，见「条目型」第 4 条。
- **简明解释**：补齐“为什么 / 怎么做 / 什么时候不成立”中的至少一项。不要复述标题换个说法。
- **例子 / 自测**：二者取一。例子优先原文自带；自测题必须能在本卡范围内作答。
- **兜底**：若一个知识点既无原文例子、也写不出合格的自测题，说明它多半还停留在“事实”层面而不是“知识”，删掉这张卡。

## 保真红线

卡片是原文的浓缩，不是原文的扩写。以下九条不得违反：

1. 只写原文能支撑的内容。原文没说的机制、原因、数据、案例，一律不补。
2. 数字、人名、术语、单位、口径与原文一致；不换算、不四舍五入、不合并统计口径。
3. **模糊限定词随数字一起保留。** 原文说“通常 2 到 3 个 RTT”，卡片不能写成“2 到 3 个 RTT”；“约”“往往”“部分”“大多数”删掉就把估计变成了断言。
4. 需要推断时显式标注“（推断：据原文第 X 段）”，或直接不写。
5. 原文表述模糊或自相矛盾时标注“原文未明确”，不要替作者下判断。
6. 区分“作者主张”与“公认事实”。观点类文章整组声明一次，不逐卡重复。
7. **不要给经验性建议套上实证外衣。** 原文说“至少访谈 5 个人”，不要写成“最小样本量为 5”——那是统计学结论，原文没这么说。
8. 自测题的答案只能来自卡片内容。
9. **不要为了好懂而添加原文没有的类比。** 类比是最高频的隐性编造。

## 自检清单

交稿前逐条过，任一为“否”就回去改：

1. 每张卡标题是否只有一个论断？数一遍并列连词。
2. 任意两张卡的“核心知识”是否互为改写？
3. 每句解释是否都能在原文找到依据？
4. 卡内出现的每个数字、专名、术语，原文都有吗？限定词带上了吗？
5. 例子来自原文，还是我编的？
6. 张数是由知识点决定的，还是在凑 5 张？
7. 删掉任意一张，其余卡是否仍然完整可读？
8. 只看卡片的人，会不会漏掉文章的主结论？
9. 条目型文章：卡片是否只是条目的分行复述？核心知识有没有回答“为什么”？
10. 原文自承的局限，是否被隐去？
11. 若原文是不给理由的纯清单，是否声明了“原文未说明理由”，而不是用通用好处填空？
12. 卡片语言是否与原文一致？

## 输出格式

```markdown
# 《文章标题或主题》知识卡片（N 张）

> 来源：用户粘贴文本 / 文件名 ｜ 识别知识点 N 个 ｜ 成卡 N 张

[卡片 1 … 卡片 N]

---

**覆盖说明**：未收录的次要内容（如有）；或原文信息不足、自承局限的具体表现。
```

- 原文有明确标题就用原标题，没有则用主题概括，不要自己起花哨名字。
- **卡片语言跟随原文语言**：英文原文出英文卡片，中文原文出中文卡片；中英混排时用占比更高的那一种，专业术语保留原文写法，不强行翻译。
- 观点型文章在引用块后加一行：`> 本文为观点文章，以下均为作者主张。`（英文原文用 `> This is an opinion piece; all cards reflect the author's claims.`）
- 卡片按逻辑顺序排（是什么 → 为什么 → 怎么做 → 边界），不要按原文段落顺序硬排。
- 覆盖说明控制在 2 行内，没有可说的就省略。
- 用户要求保存时，写入 `<原文件名>-知识卡片.md`；无来源文件名则用 `knowledge-cards.md`。只在被要求时写文件。

### 零知识点时的输出

不要输出空的卡片组，改用下面的结构，把“为什么做不到”讲清楚：

```markdown
# 输出：不生成知识卡片

> 来源：文件名 ｜ 识别知识点 0 个 ｜ 成卡 0 张

## 为什么不出卡

| 原文内容 | 为什么不能成卡 |
| --- | --- |
| 逐条列出候选内容 | 说明它缺的是解释、数据还是可验证性 |

## 可以改做什么

- 要信息摘要：可以直接给要点摘要，不套卡片格式。
- 要可复习的知识：说明需要什么类型的材料。
```

## 示例

原文（节选）：

> 睡眠不足对记忆的影响主要发生在巩固阶段。人在深度睡眠时，海马体会把白天形成的短期记忆反复回放到新皮层，完成从临时存储到长期存储的转移。因此熬夜背书的效果往往很差：编码阶段并没有问题，被切断的是当晚的转移过程。需要注意的是，这种损害不能靠周末补觉完全弥补，回放的时间窗口集中在入睡后的前三个睡眠周期。

合格产出：

```markdown
### 卡片 1｜睡眠不足损害记忆，主要发生在记忆巩固阶段

**核心知识**：睡眠不足对记忆的破坏不在“记不住”，而在“存不下”。

**简明解释**：深度睡眠时海马体将白天的短期记忆回放给新皮层，完成向长期存储的转移。熬夜切断了这一转移过程，编码环节本身并未受损，所以表现为“当时记住了，之后想不起来”。

**例子 / 自测**：熬夜背书效果差——编码正常，被切断的是当晚的巩固过程。

### 卡片 2｜补觉无法完全挽回已损失的巩固效果

**核心知识**：记忆回放集中在入睡后的前三个睡眠周期，错过即错过。

**简明解释**：原文指出这种损害不能靠周末补觉完全弥补。原因是回放的时间窗口集中且靠前，事后延长睡眠无法回溯已经错过的窗口。

**例子 / 自测**：
问：为什么周末睡到中午，也补不回熬夜那晚背的内容？
答：回放窗口集中在入睡后前三个周期，事后补觉无法回到该窗口。
```

反例（同一段原文的错误切法）：

- ❌ 标题写成“睡眠与记忆的关系”——是话题不是论断，无法判断真假。
- ❌ 把“海马体回放”和“前三个睡眠周期”塞进一张卡——两个独立机制，应分开。
- ❌ 解释里加“所以学生应该十一点前睡觉”——原文没有的行为建议，属于编造。
- ❌ 补一句“就像电脑把内存写入硬盘”——原文没有的类比。

## 常见失败模式

| 症状 | 修正 |
| --- | --- |
| 8 张里有 3 张在说同一件事 | 合并，总数降到真实值 |
| 标题是“XX 的重要性 / 价值 / 意义” | 改成可判定的陈述句 |
| 标题是把小标题或操作命令照抄 | 改写成它成立的原因；原文无理由则走规范模式并如实声明 |
| 纯清单被写成“这样能提高效率” | 删掉通用好处，原文没说的理由不要补 |
| 解释里出现原文没有的原因 | 删除，或标注为推断 |
| 一张卡塞了“三个要点” | 拆卡，或只留最重要的一个 |
| 例子是通用泛例（“比如工作中……”） | 换原文实例；没有就改成自测题 |
| 为了凑够 5 张把一句话拆成三张 | 合并，如实说明知识点不足 |
| 卡内出现“研究表明”但原文没给来源 | 删掉，或写明原文的具体依据 |
| 数字丢了“通常 / 约 / 部分” | 补回限定词，别把估计写成定论 |
| 观点文章读起来像事实陈述 | 加整组声明，解释里标出作者的论证路径 |

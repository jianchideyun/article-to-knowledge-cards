# 《为什么 QUIC 能比 TCP 更快》知识卡片（8 张）

> 来源：tests/samples/01-quic.md ｜ 识别知识点 8 个 ｜ 成卡 8 张

### 卡片 1｜QUIC 把传输层与加密层合并，首次连接只需 1 个 RTT

**核心知识**：TCP + TLS 首次连接通常要 2 到 3 个 RTT，QUIC 压到 1 个。

**简明解释**：TCP 需要三次握手消耗一个完整 RTT，再叠加 TLS 握手才能传应用数据。QUIC 在第一个数据包里同时携带连接建立与密钥协商信息，两步并作一步。对访问过的站点，客户端缓存了服务端配置，可做到 0-RTT。

**例子 / 自测**：首次访问 HTTPS 站点通常要 2 到 3 个 RTT 才开始传数据，QUIC 首次 1 个 RTT、再次 0 个 RTT。

### 卡片 2｜网络延迟越高，QUIC 省下的握手时间越值钱

**核心知识**：QUIC 的收益是绝对值，延迟越高，首屏改善越明显。

**简明解释**：省下的是固定个数的 RTT，每个 RTT 的时长取决于网络延迟。低延迟链路里省下的几十毫秒可忽略，高延迟链路里同样的 RTT 数量对应更大的绝对时间，因此改善最显著。

**例子 / 自测**：自测——为什么同一个 QUIC 优化，在卫星网络上的体感提升远大于局域网？
答案：省下的是 RTT 个数，单个 RTT 越长，省下的绝对时间越大。

### 卡片 3｜TCP 的按序交付是队头阻塞的根源

**核心知识**：TCP 严格按序交付，一个丢包会卡住其后所有已到达的数据。

**简明解释**：即使第 4 到第 10 个包已经到达，只要第 3 个包丢失，接收端也不能把它们交给应用层，必须等第 3 个包重传完成。这是协议层面的顺序保证带来的固有代价，不是实现缺陷。

**例子 / 自测**：第 3 个包丢失、第 4 至 10 个包已到达时，接收端仍然必须等待第 3 个包重传。

### 卡片 4｜HTTP/2 的请求复用把 TCP 队头阻塞放大到全部请求

**核心知识**：HTTP/2 多路复用共享一条 TCP 连接，一个丢包卡住所有请求。

**简明解释**：HTTP/2 的并发优势依赖于把多个请求塞进同一条 TCP 连接，但底层仍是单一有序字节流。丢包导致的停顿不再只影响一个请求，而是波及这条连接上的全部请求，因此在丢包率高的网络里 HTTP/2 反而不如预期。

**例子 / 自测**：原文指出这种放大效应在 HTTP/2 上尤其致命，被称为 TCP 层的队头阻塞。

### 卡片 5｜QUIC 消除的是跨流队头阻塞，不是流内队头阻塞

**核心知识**：QUIC 每条流有独立序号空间，一条流丢包不影响其他流。

**简明解释**：流之间互不阻塞，所以多请求并发在弱网下明显优于 HTTP/2 over TCP。但单条流内部仍然要求按序，该流上的丢包依然要等重传。把 QUIC 理解为“彻底消灭队头阻塞”是误解。

**例子 / 自测**：原文明确限定：QUIC 消除的是跨流的队头阻塞，单条流内部丢包仍须按序等待。

### 卡片 6｜QUIC 用连接 ID 而非四元组标识连接，因此能跨网络迁移

**核心知识**：连接与 IP 解耦，换网不断连。

**简明解释**：TCP 连接由源 IP、源端口、目的 IP、目的端口四元组标识，手机从 Wi-Fi 切到蜂窝网时源 IP 变化，四元组失配，连接必须重建。QUIC 改用 64 位连接 ID 标识连接，只要连接 ID 不变，路径变化也能继续传输。

**例子 / 自测**：手机从 Wi-Fi 切换到蜂窝网络时，TCP 上的下载或视频通话会中断，QUIC 连接可以继续。

### 卡片 7｜QUIC 跑在 UDP 上，会被 UDP 限速和封锁逼出兜底机制

**核心知识**：部分网络限制 UDP，生产环境因此需要 QUIC/TCP 竞速回退。

**简明解释**：企业网络和运营商会限速甚至封锁 UDP，导致 QUIC 连接失败或性能劣化。浏览器通常同时尝试 QUIC 与 TCP，谁先握手成功用谁，并在 QUIC 连续失败后暂时退回 TCP。

**例子 / 自测**：原文提到的竞速机制——同时发起两种连接，先完成握手者胜出，QUIC 连续失败则退回 TCP。

### 卡片 8｜QUIC 的优势在连接建立与弱网恢复，不在稳态吞吐

**核心知识**：理想网络下 QUIC 与优化良好的 TCP 差距很小。

**简明解释**：QUIC 的收益集中在握手轮次和丢包恢复。低延迟、无丢包的链路里这些优势无从发挥，而所有数据在用户态加解密比内核态 TCP 开销更高，反而可能略慢，在低端设备上 CPU 会成为新瓶颈。

**例子 / 自测**：自测——在低延迟无丢包的机房内网里，QUIC 会明显更快吗？
答案：不会，可能因用户态加解密开销略慢；QUIC 快在建立与恢复。
